# 3. PROJECT OBJECTIVE

Build a practical flood-risk decision-support system that combines:

* real-time weather data
* rainfall analysis
* historical rainfall
* water-level information
* water-level trends/rate of rise
* weather forecasts
* historical flood data
* location information
* optional elevation/geospatial information
* machine-learning prediction
* risk classification
* explainable prediction
* future risk forecasting
* interactive maps
* early-warning alerts
* emergency-response recommendations
* a consolidated dashboard

The system should estimate:

**Flood Probability → Risk Level → Main Contributing Factors → Expected Future Risk → Recommended Action**

The system is a decision-support application.

It must NOT claim to replace official government flood warnings, emergency authorities, CWC, IMD, NDMA, or other official agencies.

# 25. MACHINE LEARNING VALIDATION

Do not use only accuracy.

Evaluate appropriate metrics such as:

* accuracy
* precision
* recall
* F1 score
* ROC-AUC where applicable
* confusion matrix

Flood prediction can have class imbalance, therefore pay particular attention to:

**Recall for flood events**

A model that misses real flood events can be more problematic than one producing some false alarms.

Do not hardcode performance numbers.

Only display metrics actually obtained from executed evaluation.

# 26. DATA LEAKAGE PREVENTION

This is mandatory.

For time-series flood prediction:

* avoid using future information to predict the past
* use chronological train/validation/test separation where appropriate
* prevent leakage from target-derived features
* document preprocessing
* fit preprocessing only on training data where required

Do not randomly split temporal data if doing so creates unrealistic leakage.
